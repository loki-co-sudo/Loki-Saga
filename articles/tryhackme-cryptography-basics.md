## この記事について

TryHackMe の「Cryptography Basics」というルームで学んだ内容を、Task 単位でまとめたノートです。Cyber Security 101 の「Cryptography」モジュールにあるルームで、暗号の基本用語、歴史的な暗号、共通鍵暗号と公開鍵暗号、そして暗号でよく使う基礎数学までを一通り扱います。暗号入門の3部作（Cryptography Basics / Public Key Cryptography Basics / Hashing Basics）の1本目にあたります。

課題の設問や答え、フラグはここには含めていません。各 Task で出てきた用語や考え方を、自分の理解として整理したものです。

ちょうどこのルームを進めていたとき、量子コンピュータが公開鍵暗号を破るという話題を調べていました。RSA や Diffie-Hellman は「素因数分解」や「離散対数」という計算の難しさに寄りかかっていて、Shor のアルゴリズムを積んだ十分大きな量子コンピュータができると、その難しさが崩れます。一方で、このルームで「安全」と説明される AES のような共通鍵暗号は、鍵長を伸ばせば当面問題ないとされています。なぜ公開鍵暗号だけが名指しで危ないのか。その理由が腹落ちするようになったのは、このルームで「何が何の難しさを根拠にしているのか」を整理できたからでした。前提知識の地味な積み上げが、時事的なニュースを読む足場になる、という体験でした。

## Task 1: 導入

このルームで学ぶ範囲の紹介です。暗号（cryptography）は、敵対者がいる前提で安全な通信とデータ保護を実現する技術だと定義されます。「安全」という言葉には、少なくとも次の3つが含まれます。

- 機密性（confidentiality）: 通信の中身を第三者に読ませない
- 完全性（integrity）: 中身が途中で書き換えられていないと保証できる
- 真正性（authenticity）: 通信相手が本物だと確認できる

ネットワークプロトコルが「世界中の機器がつながる」ことを実現したのに対して、暗号は「そのつながりを信頼できる」ことを実現した、という対比が紹介されていました。

**学んだこと**

暗号の話は仕組みから入ると細部で迷子になりがちですが、「結局これは3つのうちどれを守るための話か」という物差しを最初に持っておくと、後の Task がぶれずに読めました。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| cryptography | 敵対者がいる前提で、安全な通信とデータ保護を扱う技術の総称 |
| confidentiality / integrity / authenticity | 機密性・完全性・真正性。暗号が守る代表的な性質 |
| secure channel | 盗聴・改ざんされず、相手が本物だと確認できる通信経路 |

## Task 2: 暗号の重要性

暗号が実際に使われている場面と、法律・規制で暗号が要求される分野についての Task です。

日常で暗号が動いている例として、Web サイトへのログイン（認証情報の暗号化）、SSH の暗号化トンネル、オンラインバンキングでのサーバー証明書の確認、ダウンロードしたファイルの同一性チェック（ハッシュ関数）が挙げられていました。普段は意識しないけれど、裏側では常に動いている、という位置づけです。

規制の話も出てきます。クレジットカード情報を扱うなら PCI DSS（Payment Card Industry Data Security Standard）という業界基準に従う必要があり、データは保存時（at rest）も転送時（in motion / in transit）も暗号化することが求められます。医療記録については国ごとに基準が違い、米国の HIPAA・HITECH、EU の GDPR、英国の DPA などが例に挙がっていました。

**学んだこと**

「at rest」と「in transit」はセキュリティの文章で頻出の言い回しなので、ここで対にして覚えました。保存中のデータと通信中のデータで、暗号化の考え方も使う技術も変わります。また、暗号は「使いたいから使う」だけでなく「規制で使わざるを得ない」領域がある、という視点は、実務でシステムを設計するときの制約として効いてきそうです。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| PCI DSS | 決済カード業界のデータセキュリティ基準。カード情報の保存・処理・送信に最低限のセキュリティを課す |
| HIPAA / HITECH | 米国の医療情報保護に関する法律 |
| GDPR / DPA | EU の一般データ保護規則 / 英国のデータ保護法 |
| data at rest / in transit | 保存されているデータ / 通信中のデータ。両方の暗号化が現代の基本 |

## Task 3: 平文から暗号文へ

暗号を語るための基本用語を、図とともに導入する Task です。流れは次のようになります。

```
平文(plaintext) + 鍵(key) ──[暗号化関数]──▶ 暗号文(ciphertext)
暗号文(ciphertext) + 鍵(key) ──[復号関数]──▶ 平文(plaintext)
```

登場する用語は6つです。

- 平文（plaintext）: 暗号化される前の、読める状態のデータ。文書でも画像でも何でもよい
- 暗号文（ciphertext）: 暗号化後の、読めなくなったデータ。理想的には、おおよそのサイズ以外の情報は漏れない
- 暗号（cipher）: 平文と暗号文を相互に変換するアルゴリズム
- 鍵（key）: 暗号が暗号化・復号に使うビット列
- 暗号化（encryption）: cipher と鍵で平文を暗号文にする処理
- 復号（decryption）: cipher と鍵で暗号文を平文に戻す処理

ここで重要なのが、「cipher は公開されている前提で、鍵だけを秘密にする」という考え方です。これはケルクホフスの原理（Kerckhoffs's principle）と呼ばれます。逆に、アルゴリズムを秘密にすることで安全性を確保しようとするやり方は security through obscurity（隠蔽によるセキュリティ）と呼ばれ、それ単独では弱いアプローチとされています。

**学んだこと**

「アルゴリズムは公開、鍵は秘密」を明文化した原理があると知って、後の Task で出てくる「なぜ公開鍵は公開してよいのか」「なぜ鍵長が問題になるのか」という話が一本の筋でつながりました。あわせて、暗号の文脈で出てくる「不可能（infeasible）」は数学的な絶対の不可能ではなく、「現実的な時間と計算資源では解けない」という意味だという注釈も、後で効いてきます。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| plaintext / ciphertext / cipher / key / encryption / decryption | 暗号を語るための基本6語 |
| Kerckhoffs's principle | 安全性は鍵の秘匿だけに依存すべきという原則。アルゴリズムは公開前提 |
| security through obscurity | 仕組みを隠して守ろうとする考え方。単独では弱いとされる |
| computational infeasibility | 現実的な時間では解けないという意味での「不可能」 |

## Task 4: 歴史的な暗号

シーザー暗号（Caesar Cipher）を題材に、古典暗号がなぜ現代では通用しないのかを学ぶ Task です。

シーザー暗号は、各文字をアルファベット順に一定数ずらすだけの換字式暗号（substitution cipher）です。鍵は「何文字ずらすか」という数ひとつだけです。Z まで到達したら A に戻ります。

問題は鍵空間（keyspace）の狭さです。英語アルファベットは26文字で、26ずらすと元に戻るので、有効な鍵は25通りしかありません。cipher の種類が分かっていれば、25通りを順に試すだけで復号できます。全パターンを試して意味の通る文を探す、という総当たり（brute force）が現実的に成立してしまいます。ルームでも、全鍵を試して平文が復元される様子が図で示されていました。

このほか、歴史的な暗号として16世紀のヴィジュネル暗号（Vigenère cipher）、第二次大戦のエニグマ（Enigma）、冷戦期のワンタイムパッド（one-time pad）が名前だけ紹介されていました。

**学んだこと**

このルームで一番の教訓だと感じたのは、「アルゴリズムがどれだけ巧妙でも、鍵空間が小さければ総当たりで破れる」という点です。現代の暗号が長い鍵を使う理由が、逆算する形で理解できました。シーザー暗号を解く課題もありましたが、鍵が25通りしかないので、考え方さえ分かれば手を動かすだけで済みます。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| Caesar Cipher / shift cipher | 各文字を一定数ずらす換字式暗号。鍵はずらし量のみ |
| substitution cipher | 文字を別の文字に置き換える方式の総称 |
| brute-force attack | 取りうる鍵をすべて試す攻撃。鍵空間が小さいほど有効 |
| keyspace | 取りうる鍵の全体。小さいほど総当たりに弱い |
| Vigenère cipher / Enigma / one-time pad | 歴史的な暗号の代表例 |

## Task 5: 暗号の種類

暗号を共通鍵（symmetric）と公開鍵（asymmetric）の2つに大きく分ける Task です。

**共通鍵暗号（symmetric encryption）** は、暗号化と復号に同じ鍵を使います。秘密鍵暗号（private key cryptography）とも呼ばれます。この方式の弱点は鍵の配送です。パスワード保護した文書をメールで送る例が分かりやすく、文書と同じ経路でパスワードも送ってしまうと、その経路を盗み見た相手に両方渡すことになります。安全な経路がまだ無いところに、安全な経路を作るための鍵を届けなければならない、というジレンマです。これを鍵配送問題（key distribution problem）と呼びます。

共通鍵暗号の代表例として、DES・3DES・AES が挙げられます。

- DES（Data Encryption Standard）: 1977年に標準化。56ビット鍵。1999年に24時間かからず鍵が破られ、移行のきっかけになった
- 3DES（Triple DES）: DES を3回適用。鍵長168ビットだが実効的な安全性は112ビット。2019年に非推奨（deprecated）。レガシーシステムに残っていることがある
- AES（Advanced Encryption Standard）: 2001年に標準化。鍵長は128・192・256ビットから選べる。現在の標準

**公開鍵暗号（asymmetric encryption）** は、暗号化と復号で異なる鍵のペアを使います。公開鍵（public key）で暗号化し、秘密鍵（private key）で復号します。公開鍵は誰に配ってもよく、秘密鍵だけを守ります。代表例は RSA、Diffie-Hellman、楕円曲線暗号（ECC）です。処理は共通鍵より遅く、鍵も長めです。RSA は2048ビット以上が推奨、ECC は256ビット鍵で RSA の3072ビット鍵に匹敵する安全性が得られるとされています。

公開鍵暗号が成り立つ根拠は、「片方向の計算は簡単だが、逆方向は現実的に不可能」という数学的な問題です。この非対称性が、公開鍵を公開したままでも安全でいられる理由になっています。

用語のまとめとして、暗号の説明でよく出てくる Alice と Bob（安全に通信したい2者を表す架空の人物）も紹介されていました。

**学んだこと**

DES → 3DES → AES の世代交代は、鍵長と「いつ危殆化したか」をセットで覚えるのがよさそうです。DES は鍵が短すぎて総当たりで破られた、3DES はつなぎ、AES がいまの選択肢、という整理です。また、公開鍵暗号を「南京錠と鍵」で捉えると分かりやすいと感じました。南京錠（公開鍵）は誰にでも配れて誰でも掛けられるが、開けられるのは鍵（秘密鍵）を持つ本人だけ、というイメージです。冒頭で触れた量子コンピュータの話は、まさにこの「逆方向は現実的に不可能」という前提が崩れる、という話でした。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| symmetric / asymmetric encryption | 共通鍵暗号 / 公開鍵暗号。鍵が1つか、ペアか |
| key distribution problem | 鍵を安全に相手へ届ける難しさ。共通鍵暗号の弱点 |
| DES / 3DES / AES | 共通鍵暗号の標準の世代。現在は AES |
| RSA / Diffie-Hellman / ECC | 公開鍵暗号の代表。ECC は短い鍵で高い安全性 |
| public key / private key | 公開鍵（配ってよい） / 秘密鍵（守る） |
| Alice / Bob | 暗号の説明で使われる通信当事者の定番の名前 |

## Task 6: 基礎数学

暗号でよく使う2つの数学演算、XOR と剰余（modulo）を学ぶ Task です。

**XOR（exclusive OR、排他的論理和）** は、2つのビットを比べて、異なれば1、同じなら0を返す演算です。記号は ⊕ または ^ で、ビットごとに適用します。暗号で効いてくるのは次の性質です。

- `A ⊕ A = 0`（同じ値をもう一度 XOR すると打ち消える）
- `A ⊕ 0 = A`（0 と XOR しても変わらない）
- 交換法則（`A ⊕ B = B ⊕ A`）と結合法則（`(A ⊕ B) ⊕ C = A ⊕ (B ⊕ C)`）が成り立つ

この性質から、平文 P と鍵 K に対して `C = P ⊕ K` で暗号化し、`C ⊕ K = (P ⊕ K) ⊕ K = P ⊕ (K ⊕ K) = P ⊕ 0 = P` で復号できます。暗号化も復号も「鍵で XOR する」という同じ操作で済みます。ただし実用には平文と同じ長さの鍵が必要で、そこが現実の難しさになります。

**剰余（modulo）** は、`X % Y` で X を Y で割った余りを表します。日常では割り算の商を気にしますが、暗号では余りが主役です。重要な性質は「逆算できない」ことで、`x % 5 = 4` を満たす x は無数にあります。また、`a % n` の結果は必ず 0 から n − 1 の範囲に収まります。大きな数を扱うことになるので、電卓で足りなければ Python の `%` 演算子や WolframAlpha を使うとよい、という実務的な補足もありました。

**学んだこと**

XOR 暗号の復号が成り立つ理由を、`A ⊕ A = 0` と結合法則から式で追えるようにしておくと、この後 one-time pad やストリーム暗号（stream cipher）を学ぶときの土台になりそうです。剰余の「逆算できない」性質は、公開鍵暗号の「片方向は簡単、逆は困難」という話と地続きで、剰余べき乗（modular exponentiation）という形で RSA や Diffie-Hellman に効いてきます。計算問題の課題もありますが、XOR は桁をそろえてビットごとに書くだけ、剰余は Python の `%` に任せれば済みます。

**関連キーワード**

| キーワード（英語） | 説明 |
| --- | --- |
| XOR (exclusive OR) | 2ビットが異なれば1、同じなら0。記号は ⊕ または ^ |
| one-time pad / stream cipher | XOR を基礎に置く暗号方式 |
| modulo operation | 割り算の余り。`%` や `mod` と書く |
| modular arithmetic | 一定の法で数が循環する計算体系。時計算とも |
| modular exponentiation | 剰余べき乗。RSA / Diffie-Hellman の中核演算 |

## Task 7: まとめ

ルーム全体の振り返りです。暗号の重要性、共通鍵暗号と公開鍵暗号、XOR と剰余の演算を扱ったこと、そして次のルーム「Public Key Cryptography Basics」で公開鍵暗号の中身に入っていく、という予告でした。

**学んだこと**

このルームで扱った用語と概念は、次の2ルーム（Public Key Cryptography Basics / Hashing Basics）を読む前提になります。振り返りとして、次の点を自分の言葉で説明できるかを確認しました。

- 暗号が守るのは機密性・完全性・真正性の3つ
- 基本6語（plaintext / ciphertext / cipher / key / encryption / decryption）
- アルゴリズムは公開、安全性は鍵の秘密に依存する（Kerckhoffs's principle）
- シーザー暗号は鍵空間が25通りしかなく、総当たりで破れる
- 共通鍵は DES → 3DES → AES、弱点は鍵配送問題
- 公開鍵は RSA / Diffie-Hellman / ECC、「片方向は簡単、逆は困難」な問題に基づく
- XOR と剰余の基本性質、特に `A ⊕ A = 0` と剰余の非可逆性
