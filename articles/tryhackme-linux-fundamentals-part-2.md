## Task 1: Introduction

このルームは「Linux Fundamentals」シリーズの第2部にあたります。第1部ではブラウザ内蔵のターミナルを使いましたが、第2部からは実際にSSH(Secure Shell、リモートのマシンに安全に接続するためのプロトコル)を使って、自分の端末から離れたマシンにログインする、より実務に近いスタイルに変わります。

扱う内容は大きく分けて次の4つです。

- SSHでリモートマシンにログインする方法
- コマンドに「フラグ・引数」を付けて挙動を変える方法
- ファイルのコピーや移動など、ファイルシステム操作の応用
- ファイル・フォルダへのアクセス権(パーミッション)の仕組み

これらはどれも、CTF(Capture The Flag、セキュリティ技術を競う演習)やペネトレーションテストの現場で、リモートマシンに入ったあとに必ず使うことになる基礎スキルです。Part 1が「Linuxに慣れる」段階だとすると、Part 2は「Linuxを実際の道具として使いこなす」段階に一歩進んだ内容だと言えます。

**学習すべき要点**

- SSH(Secure Shell)でリモートマシンにログインする流れ — 攻略対象のマシンに実際に入って作業するための、最も基本的な手段だから
- コマンドのフラグ・引数(Flags and Arguments) — 同じコマンドでも挙動を細かく制御できるようになり、実務での操作の幅が大きく広がるため
- ファイルシステム操作の応用(コピー・移動など) — ファイルを扱う基本操作は、調査でもシステム管理でも頻繁に使うから
- パーミッション(Permissions)の考え方 — 「誰が何にアクセスできるか」を理解することは、権限昇格(Privilege Escalation)などセキュリティの重要テーマにも直結するため

## Task 2: Accessing Your Linux Machine Using SSH (Deploy)

Task 2からいよいよ実践パートです。Part 1のようなブラウザ内蔵のターミナルではなく、「AttackBox」という踏み台(自分の代わりに操作するクラウド上のLinuxマシン)から、SSHで別のLinuxマシン(Labマシン)にログインする、より実際の現場に近いスタイルになります。

SSH(Secure Shell)は、リモートのマシンに安全にログインして操作するためのプロトコルです。「安全に」というのがポイントで、通信内容が暗号化(Cryptography)されているため、途中でネットワークを盗聴されても中身を読み取られにくくなっています。これは今後、CTFやペネトレーションテストで「侵入したマシンにリモートから接続する」場面で必ず使うことになる、基本中の基本の技術です。

SSHでログインするときのコマンドの形はとてもシンプルで、次の形式を覚えておけば、ほとんどの場面で使い回せます。

```
ssh ユーザー名@IPアドレス
```

必要なのは「リモートマシンのIPアドレス」と「ログインするアカウントの正しい認証情報(Credentials)」の2つだけです。TryHackMeのAttackBoxは、クラウド上でホストされたUbuntu Linuxマシンで、ブラウザ経由で操作でき、このAttackBoxから対象のLabマシンにSSH接続する、という2台構成が基本になります。

パスワード入力時に何も表示されないというのは、初めて見ると「打ち間違えた?」「フリーズした?」と不安になりがちなポイントです。これはSSHに限らず多くのLinuxのパスワード入力で共通の仕様で、セキュリティ上あえて入力内容を表示しない設計になっています。見えなくてもきちんと入力されているので、落ち着いてそのままEnterを押せば問題ありません。

**学習すべき要点**

- SSH(Secure Shell)が「暗号化された安全なリモート接続」であること — 平文(暗号化されていない)通信との違いを理解しておくと、後々の暗号化・盗聴のテーマにもつながるため
- `ssh ユーザー名@IPアドレス` という基本構文 — この形はどんなLinux環境でもほぼ共通で使う、最も頻出するコマンドの1つだから
- AttackBox(踏み台マシン)とLabマシン(攻略対象)という2台構成の考え方 — 実際のペネトレーションテストでも「自分の攻撃用マシン」と「対象マシン」を分けて考える基本構造だから
- パスワード入力時に文字が表示されない仕様 — 初見で戸惑いやすいポイントなので、事前に知っておくと安心して操作できるため

**関連キーワード**

| キーワード(英語) | 説明 |
| --- | --- |
| SSH (Secure Shell) | リモートマシンへ暗号化された通信で安全に接続し、コマンドラインを操作するためのプロトコル |
| Protocol(プロトコル) | 機器やソフトウェア同士が通信するときの、共通のルール・取り決め |
| Cryptography(暗号技術) | データを第三者に読み取られないように変換し、正当な受信者だけが元に戻せるようにする技術 |
| Deploy(デプロイ) | 仮想マシンやアプリケーションを起動し、実際に使える状態にすること |
| AttackBox | TryHackMeが提供する、クラウド上でホストされたUbuntu Linuxの攻撃用マシン。ブラウザから操作できる |
| Credentials(認証情報) | ログインに必要なユーザー名・パスワードなどの情報の総称 |

## Task 3: Introduction to Flags and Switches

コマンドは基本的に「何も付けなければデフォルトの動き」をします。例えば`ls`はただ実行すると見えているファイル・フォルダだけを表示しますが、`-a`(`--all`の短縮形)というフラグを付け足すことで「隠しファイルも含めて全部表示する」という風に、動きを拡張できます。Linuxでは、こういうハイフン付きのオプション(フラグ・スイッチ)を付け加えることで、同じコマンドでも細かく挙動をコントロールできるようになっています。

`-a`のような1文字の短い書き方を「ショートオプション(short option)」、`--all`のような単語そのものを使う書き方を「ロングオプション(long option)」と呼ぶことが多いです。両方とも同じ意味ですが、ロングオプションの方が意味が分かりやすく、ショートオプションの方がタイプ数が少なくて済む、という違いがあります。

あるコマンドがどんなフラグを受け付けるのか分からないときに頼れるのが、`--help`と`man`コマンドです。`--help`はそのコマンドを実行するとターミナルにサッと一覧が表示される簡易版、`man <コマンド名>`はそれをさらに詳しくした正式なマニュアルという位置づけになります。「困ったら公式ドキュメントを最初に見る」という考え方は、Linux操作全般に通じる姿勢です。

manページは表示されたあと、ターミナルの中でスクロールしながら読む「ページャー(pager)」という専用の画面に切り替わります。矢印キーやスペースキーなどでページ内を移動しながら読み進める形式で、実際に`man ls`などを実行して手を動かしながら操作方法を確かめてみると理解が深まります。

**学習すべき要点**

- フラグ・スイッチ(Flags / Switches)の基本 — コマンドの動作を柔軟に変えられるようになり、Linux操作の応用力が一気に上がるから
- ショートオプション(例: `-a`)とロングオプション(例: `--all`)の違い — 同じ意味の書き方が2通りあることを知っておくと、他人のコマンド例を読むときに混乱しないため
- `--help`とmanページ(`man <コマンド名>`)の使い分け — 「今すぐ簡単に確認したい」か「じっくり詳しく調べたい」かで使い分けられるようになるため
- manページの操作方法(ページャーでのスクロール) — 初めて見ると戸惑いやすいが、実際に手を動かして覚えておくと、以後ずっと使う基本操作になるから

**関連キーワード**

| キーワード(英語) | 説明 |
| --- | --- |
| Flag / Switch | コマンドの動作を変更するために付け加える、ハイフン付きのオプション |
| Argument(引数) | コマンドに渡す追加情報。フラグだけでなく、対象のファイル名なども含む |
| Short option / Long option | `-a`のような短縮形の書き方と、`--all`のような単語そのものの書き方 |
| Hidden file(隠しファイル) | ファイル名が"."から始まる、通常の一覧表示では表示されないファイル |
| Default behaviour(デフォルトの動作) | オプションを何も指定しなかったときの、コマンドの標準的な振る舞い |
| Pager(ページャー) | `man`コマンドの出力など、長いテキストをスクロールしながら閲覧するための画面・仕組み |

## Task 4: Filesystem Interaction Continued

このTaskでは、ファイルシステムを操作するための、実際の作業で頻繁に使う6つのコマンドを扱いました。

| コマンド | 正式名称 | 用途 |
| --- | --- | --- |
| touch | touch | ファイルを作成する |
| mkdir | make directory | フォルダを作成する |
| cp | copy | ファイルやフォルダをコピーする |
| mv | move | ファイルやフォルダを移動する |
| rm | remove | ファイルやフォルダを削除する |
| file | file | ファイルの種類を判定する |

コマンド名がそのまま英単語の略になっているものが多いので、正式名称とセットで覚えると忘れにくくなります(`mkdir`=make directory、`rm`=removeなど)。

いくつか注意しておきたい点があります。

- `touch`は「空のファイルを作るだけ」で、中身までは書いてくれません。文章を実際に書き込みたいときは`echo`コマンドや`nano`のようなテキストエディタが別途必要になります。
- `rm`でディレクトリ(フォルダ)ごと削除したいときは、単体の`rm`ではなく`-R`スイッチ(再帰的に処理するという意味の「Recursive」の頭文字)を付ける必要があります。付け忘れると削除できません。
- `mv`は「移動」だけでなく「名前の変更(Rename)」にも使われます。Linuxの内部では、ファイルを別の名前に付け替えることと、別の場所(パス)に移すことは、本質的に同じ操作として扱われています。

最後の`file`コマンドは、拡張子に頼らずファイルの中身の実体(テキストなのか、実行ファイルなのか、画像なのかなど)を判定してくれるコマンドです。ファイルの拡張子はあくまで「人間が分かりやすくするための飾り」であって、中身の種類を保証するものではありません。CTFなどでは拡張子が偽装されたファイルに出会うこともあるので、`file`コマンドで実体を確認する習慣は今後も役立ちます。

**学習すべき要点**

- ファイル・フォルダの作成(`touch` / `mkdir`)の基本 — 何かを新しく用意する、最も基礎的な操作だから
- ファイルの削除(`rm`)と`-R`スイッチの役割 — ディレクトリを消すときに必要な条件を知らないと、意図した通りに削除できないため
- コピー(`cp`)と移動(`mv`)の違い、`mv`が名前変更にも使えること — 似たコマンドの使い分けを誤ると、意図せずファイルを上書き・消失させるリスクがあるから
- `file`コマンドで拡張子に頼らずファイルの実体を確認する習慣 — 拡張子は偽装されうるため、セキュリティ調査の現場で特に重要な考え方だから

**関連キーワード**

| キーワード(英語) | 説明 |
| --- | --- |
| touch | 空のファイルを新規作成する、または既存ファイルのタイムスタンプを更新するコマンド |
| mkdir (make directory) | 新しいディレクトリ(フォルダ)を作成するコマンド |
| cp (copy) | ファイルやフォルダをコピーするコマンド |
| mv (move) | ファイルやフォルダを移動する、または名前を変更するコマンド |
| rm (remove) | ファイルやフォルダを削除するコマンド。ディレクトリの削除には`-R`(再帰的処理)が必要 |
| file | 拡張子に依存せず、ファイルの実体の種類を判定するコマンド |
| Extension(拡張子) | ファイル名の末尾に付く、ファイルの種類を示す文字列(例: `.txt`)。中身を保証するものではない |
| Recursive(再帰的) | フォルダの中身も含めて、階層構造すべてに同じ処理を適用すること |

## Task 5: Permissions 101

Task 5のテーマはLinuxの権限管理(パーミッション、Permission)です。`ls -l`(または`ls -lh`)を実行すると出てくる先頭の記号列(例: `rw-r--r--`)がパーミッションの正体で、10文字あるうちの最初の1文字はファイルかディレクトリかを示す記号、残りの9文字が「所有者(Owner)」「グループ(Group)」「その他(Others)」の3つのグループに3文字ずつ分かれています。それぞれの3文字が、読み取り(r)・書き込み(w)・実行(x)の許可・不許可を表しています。

Linuxの権限管理で面白いのは、「ファイルの所有者は1人でも、グループ単位で別のアクセス権を設定できる」という点です。例えば、Webサーバーそのものを動かすユーザーと、顧客としてファイルをアップロードするユーザーを分けつつ、必要な範囲だけアクセスを許可する、という設計がこの仕組みの柱になっています。

ユーザーを切り替えるには`su`(switch user)コマンドを使います。単に`su ユーザー名`とするか、`-l`(`--login`)スイッチを付けるかで、切り替え後にどのディレクトリに移動するかが変わります。`-l`を付けた方が、そのユーザーが最初からログインしたときにより近い状態(環境変数なども含む)になります。

パーミッションはシンボリック表記(`rwxr-xr-x`など)だけでなく、数値表記(`755`など)でも扱われます。r=4、w=2、x=1という値を、所有者・グループ・その他それぞれで足し算するだけなので、慣れれば頭の中でもすぐに計算できるようになります。

| シンボリック表記 | 数値表記 | 意味 |
| --- | --- | --- |
| rwxr-xr-x | 755 | 所有者は何でもできる。その他のユーザーは読み取り・実行のみ可能 |
| rw-r--r-- | 644 | 所有者は読み書き可能。その他のユーザーは読み取りのみ可能 |
| rwx------ | 700 | 所有者のみがアクセス可能 |

この数値表記は`chmod`(change mode、パーミッションを変更するコマンド)を使う際に必須の知識です。数値表記を読めるようになると、「このファイルは誰でも書き換えられる状態になっていて危険だ」といった、セキュリティ上の問題にもすぐ気づけるようになります。

**学習すべき要点**

- `ls -l`で表示されるパーミッション表記(所有者・グループ・その他の3区分) — ファイルへのアクセス可否を判断する、Linuxの権限管理の基本になるから
- Read / Write / Execute(r / w / x)という3種類の権限の意味 — chmodなど権限変更コマンドを扱う際の前提知識になるため
- `su`コマンドによるユーザー切り替えと、`-l`スイッチの有無による挙動の違い — 権限が異なる別ユーザーとして操作する場面は、CTFや実務の権限昇格(Privilege Escalation)の場面でもよく出てくるから
- シンボリック表記と数値表記(例: `rwxr-xr-x` = `755`)の相互変換 — `chmod`コマンドを使いこなすために必須の計算方法だから

**関連キーワード**

| キーワード(英語) | 説明 |
| --- | --- |
| Permission(パーミッション) | ファイルやディレクトリに対する、読み取り・書き込み・実行の許可設定 |
| Owner / Group / Others | パーミッションが適用される3つの対象区分(所有者・所有グループ・それ以外のユーザー) |
| su (switch user) | 別のユーザーへ切り替えるためのLinuxコマンド |
| root | Linuxにおける最上位の管理者ユーザー。基本的にすべての操作が許可されている |
| sudo | 一時的に管理者(root)権限でコマンドを実行するための仕組み |
| chmod (change mode) | ファイルやディレクトリのパーミッションを変更するコマンド |
| Environment variable(環境変数) | シェルやプログラムが参照する、キーと値のペアで管理される設定情報 |

## Task 6: Common Directories

Task 6は、Linuxのファイルシステムの中でも特に重要な4つのディレクトリ(`/etc` `/var` `/root` `/tmp`)を扱いました。

`/etc`は、システム全体の設定ファイルが集まる場所です。中でも`passwd`と`shadow`は、ユーザーアカウントの情報やパスワードのハッシュ(暗号化された値)を管理している重要なファイル。`sudoers`は「誰がroot権限でコマンドを実行できるか」を定義しているファイルで、権限まわりを調べるときによく登場します。

`/var`は「頻繁に書き換わるデータ」の置き場所です。特に`/var/log`にはシステムやサービスのログファイルが溜まっていくので、何か問題が起きたときの調査(トラブルシューティング)や、侵入の痕跡を探す際の定番の確認場所になります。

`/root`は名前が紛らわしいポイントです。一般ユーザーのホームディレクトリは`/home/ユーザー名`に置かれるのに対して、rootユーザーだけは特別に`/root`という専用のディレクトリをホームとして持っています。「rootのホームは/home/rootだろう」と思い込んでしまうと迷子になりやすいので、意識しておく価値があります。

`/tmp`は「一時的な作業スペース」です。多くの環境でデフォルトのまま誰でも書き込める設定になっていることが多く、CTFやペネトレーションテストでは、持ち込んだスクリプトやツールを一時的に置く場所としてよく使われます。ただし再起動で中身が消えてしまう(揮発性)という性質も、メモリ(RAM)とよく似た特徴として覚えておくとよいでしょう。

**学習すべき要点**

- `/etc`が設定ファイルの集約場所であること(`passwd` `shadow` `sudoers`など) — ユーザーや権限に関する調査を行うときに、必ず確認することになる場所だから
- `/var`、特に`/var/log`がログの置き場所であること — システムの挙動を調べたり、トラブルシューティングをしたりする際の基本的な手がかりになるため
- `/root`がrootユーザー専用のホームディレクトリであること(`/home/root`ではない) — 直感と違う点なので、覚え間違えやすいポイントとして意識しておく必要があるから
- `/tmp`が揮発性で、多くの場合誰でも書き込めること — 一時的な作業や調査用ツールの置き場所として、実務上よく利用される特性だから

**関連キーワード**

| キーワード(英語) | 説明 |
| --- | --- |
| /etc | システム全体の設定ファイルが置かれるディレクトリ |
| /var | ログなど、頻繁に書き換わるデータが置かれるディレクトリ |
| /root | rootユーザー専用のホームディレクトリ |
| /tmp | 一時的なデータを保存する、揮発性のディレクトリ |
| sudoers | `sudo`でroot権限のコマンドを実行できるユーザー・グループを定義するファイル |
| passwd / shadow | ユーザーアカウントの情報やパスワードハッシュを管理するファイル |
| Volatile(揮発性) | 電源やセッションが切れると内容が消えてしまう性質 |
| Enumeration(列挙) | 攻略・調査対象のシステムから、有用な情報を洗い出すこと |
